# 设计规范

适用于 Studio、Relay 的产品界面和共享 UI。组件层用 ReUI，底座是仓库现有的 shadcn（base-vega）+ Base UI，主题变量在 `tooling/tailwind/theme.css`；本文定义用途和目标值，数值以主题文件为准。

## 1. 方向

界面要清晰、精确、有活力，适合长时间工作，同时有足够的视觉丰富度和辨识度。

Studio 以中文工作界面为主，承载多渠道沟通及相关工作。Relay 面向渠道连接、API 使用和运行诊断。两者继承同一套品牌、主题与基础组件，通过信息组织和内容密度表达任务差异。

- 蓝色是主品牌强调，允许有吸引力的色彩表达。
- 中文优先校准字体、层级、行高和密度。
- 工作界面要有区域层次、主次对比和真实内容的丰富度。
- 基础组件复用；品牌表达通过统一主题、组件变体、页面布局与业务内容实现。
- 「高级感」不等于去掉色彩、缩小字号、降低文字对比度或大面积空白。

## 2. 品牌与产品表达

### 2.1 命名

对外完整名称 `Vesact Studio`、`Vesact Relay`，进入产品后简写 `Studio`、`Relay`。没有正式字标前用排版字标。产品内不重复展示全套品牌名称，不加口号。

### 2.2 共同气质

| 特征     | 应表现为                                 | 应避免                               |
| -------- | ---------------------------------------- | ------------------------------------ |
| 清晰     | 主任务明确，阅读与操作路径容易辨认       | 所有元素同样醒目                     |
| 精确     | 对齐稳定，状态可信，组件行为一致         | 用装饰代替信息结构                   |
| 有活力   | 有辨识度的蓝色、内容图片、清楚的选中反馈 | 页面完全灰白或任意堆砌彩色           |
| 有层次   | 区域明暗、文字轻重、疏密和内容形式有变化 | 相同白底、相同边框、相同灰字铺满页面 |
| 适合工作 | 高频内容易读，操作紧凑，信息能持续增长   | 宣传图式大标题、大留白和无意义装饰   |

### 2.3 产品差异

| 维度       | Studio                             | Relay                              |
| ---------- | ---------------------------------- | ---------------------------------- |
| 信息主角   | 客户、消息、内容、下一步工作       | 连接、操作、事件、调用结果         |
| 主要结构   | 会话列表、阅读区、编辑区、辅助信息 | 列表、详情、配置、日志与诊断       |
| 密度       | 列表紧凑，阅读舒展                 | 数据紧凑，错误说明充分             |
| 语言       | 中文任务语言，必要时解释术语       | 中文说明结合标准技术名词           |
| 丰富度来源 | 头像、消息类型、原文与译文、附件   | 平台标识、状态、时间线、结构化数据 |

两个产品共用品牌蓝，不用「Relay 深色、Studio 浅色」来区分。

## 3. 层次与丰富度

### 3.1 四个层次

一个工作页面要建立以下层次，不要求机械使用四种背景色：

1. **应用外壳**：品牌和全局导航，形成稳定识别。
2. **任务组织区**：会话列表、筛选或资源列表，强调扫描和选择。
3. **主工作区**：内容阅读、编辑或诊断的焦点，拥有最大的有效面积。
4. **辅助信息区**：客户资料、操作上下文等，信息完整但视觉退后。

相邻区域至少通过背景明暗、边界、留白、内容密度中的两项形成差异。不能只靠几条极淡分隔线区分所有面板。

### 3.2 蓝色形成连续的品牌表达

品牌蓝出现在字标、当前导航、会话选中态、发出消息、主按钮和键盘焦点中，不同位置用不同深浅。

- 实色蓝用于主操作、少量品牌锚点和重要计数。
- 浅蓝用于选中背景、发出消息背景及轻量强调。
- 深蓝用于浅蓝表面上的文字和图标。
- 链接和焦点沿用品牌色，但仍要有明确的链接或焦点形式。
- 不把所有标签、图标和状态都染成蓝色。

单个页面通常只有一个主操作组使用最强的实色强调。危险操作的辨识度由业务风险决定，不为这条原则降低。

### 3.3 丰富度来自真实内容

使用与任务相关的头像、企业标识、产品图片、文件类型、消息引用、译文、状态和时间线。有对应业务数据时才显示；缺头像用设计一致的文字回退，缺图片不补无关图库照片。设计样张可以用明确标记的示例数据。

### 3.4 允许与限制

允许：局部浅色表面、明确的品牌色块、轻微层叠、少量有意义的阴影、适中的圆角、自然内容图片。

限制：工作台大面积蓝紫渐变、玻璃模糊、发光背景、每个模块独立大卡片、整页统一降对比度。

登录和引导页可以用更强的品牌表现，不迁移到高频工作页面。

### 4.2 文字

| 语义                 | 变量                          | 现值               | 目标                                    |
| -------------------- | ----------------------------- | ------------------ | --------------------------------------- |
| 客户名、标题、主内容 | `--foreground`                | `oklch(0.145 0 0)` | 保持                                    |
| 常规说明、摘要、译文 | `--muted-foreground`          | `oklch(0.556 0 0)` | slate-600 `oklch(0.446 0.043 257.281)`  |
| 时间和辅助标签       | `--muted-foreground` + 小字号 | —                  | 不另设变量                              |
| 不可用               | 组件的 `disabled:opacity-50`  | —                  | 不用 `--muted-foreground` 表示 disabled |
| 实色品牌表面上的文字 | `--primary-foreground`        | blue-50            | 改为白 `oklch(1 0 0)`                   |

不通过整块内容低 opacity 做「高级感」。边框可以轻，正常文本必须易读。

### 4.3 状态色

现有 `--success`、`--warning`、`--info`、`--destructive` 是实色语义（底色 + `-foreground` 文字）。浅色底用 `bg-<状态>/10 text-<状态>`，不再另设一套变量。

| 状态        | 变量            | 现值                         | 目标                                  | 示例               |
| ----------- | --------------- | ---------------------------- | ------------------------------------- | ------------------ |
| success     | `--success`     | green-800                    | 保持                                  | 连接有效、操作完成 |
| warning     | `--warning`     | yellow-700                   | amber-700 `oklch(0.555 0.163 48.998)` | 授权即将失效       |
| destructive | `--destructive` | `oklch(0.577 0.245 27.325)`  | 保持                                  | 发送失败、连接失效 |
| info        | `--info`        | violet-500，文字 violet-900  | blue-600，文字白                      | 信息说明、处理中   |
| neutral     | `--secondary`   | `oklch(0.967 0.001 286.375)` | 保持                                  | 未开始、普通元数据 |

正文对比度以 4.5:1 为验收基线；状态同时用文字，必要时加图标，不能只靠颜色。

### 4.4 暗色

`.dark` 块已有全部变量，按浅色的对应关系单独映射，不机械反转：

| 语义     | 变量           | 暗色目标                                              |
| -------- | -------------- | ----------------------------------------------------- |
| 应用底层 | `--background` | 保持 `oklch(0.145 0 0)`                               |
| 容器     | `--card`       | 保持 `oklch(0.205 0 0)`                               |
| 品牌     | `--primary`    | blue-600 `oklch(0.546 0.245 262.881)`，比浅色提亮一级 |
| 浅蓝表面 | `--brand-soft` | blue-950 `oklch(0.282 0.091 267.935)`                 |
| 浅蓝文字 | `--brand-ink`  | blue-200 `oklch(0.882 0.059 254.128)`                 |
| 状态浅底 | `bg-<状态>/15` | 同一写法，透明度略高                                  |

## 5. 中文与混合语言排版

### 5.1 字体

两个 app 的 `globals.css` 用系统字体栈，不加载外部字体（Google Fonts 只有拉丁字形，国内访问不稳）：

```css
--font-sans:
	-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB",
	"Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
```

`theme.css` 里 `:root:lang(zh)` 的字距、行高和标题字号覆盖保留。代码、API 字段、ID 用等宽字体；数字列用 `tabular-nums`；中文导航和段落不用等宽。

### 5.2 字号基线

| 用途                 | 字号 / 行高      | 字重    |
| -------------------- | ---------------- | ------- |
| 页面标题             | 22 / 30 px       | 600     |
| 工作面板标题         | 16 / 24 px       | 600     |
| 客户名、主列表字段   | 14 / 22 px       | 500–600 |
| 导航、按钮、表单     | 14 / 22 px       | 400–500 |
| 消息正文             | 15 / 24 px       | 400     |
| 长文本阅读           | 16 / 26 px       | 400     |
| 译文、摘要、辅助说明 | 14 / 22 px       | 400     |
| 时间、轻量元数据     | 12–13 / 18–20 px | 400     |

实现转成 rem。12px 只用于少量辅助元数据，不用于主导航、消息正文、按钮或关键状态。

### 5.3 字重、字距与对齐

- 正文 400；可操作标签和列表主字段 500；标题或少量重点 600。
- 不把大段中文加粗，不同时用粗体、彩色、图标和实色标签重复强调同一内容。
- 中文正文保持正常字距，不沿用英文标题的负字距。
- 小号全大写英文仅用于品牌辅助署名等有限位置。
- 图标按文字视觉中心对齐。
- 中英文、数字和单位间距一致：「500 件」「24 小时」「API 调用」。

### 5.4 多语言内容

- 原文与译文保留明确边界；译文可稍弱，但仍可直接阅读。
- 不在每条短消息上重复醒目的「中文译文」大标签；用轻量标识或统一控制。
- 阿语等内容按消息块确定 `dir`，不翻转整个中文工作台。
- 长 URL、连续字符串和文件名不撑开布局。
- 中文输入法组合输入期间，Enter 不触发发送。

## 6. 尺寸、间距、圆角与阴影

### 6.1 间距

4px 节奏：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`。图标与标签 6–8；内容组内部 8–12；组件内部 12–16；面板内边距 20–24；信息组之间 24–32。同级组件对齐统一，不同任务区域允许不同密度。

### 6.2 控件尺寸

- 常规输入框、按钮 36px；紧凑工具栏控件 32px，仅用于密集操作区；主要表单控件 40px。
- 图标 16–18px，主要工具图标 20px。
- 图标按钮要有足够点击区域，触屏高频操作约 44px。

### 6.3 圆角

`--radius` 是 0.45rem，派生档位如下，不另设值：

| 对象                     | 档位                        |
| ------------------------ | --------------------------- |
| 小标签、计数             | `rounded-sm` / `rounded-md` |
| 按钮、输入框、会话选中行 | `rounded-lg`                |
| 消息气泡、编辑器、附件   | `rounded-xl`                |
| 浮层、弹窗               | `rounded-2xl`               |

圆形留给头像和确有必要的圆形操作。

### 6.4 边框与阴影

结构优先用表面与边界。阴影表达层级：菜单、浮层、弹窗，以及需要轻微抬起的编辑器。

```css
/* 轻层级 */
box-shadow: 0 1px 3px rgb(15 23 42 / 0.06);
/* 浮层 */
box-shadow: 0 8px 24px rgb(15 23 42 / 0.1);
```

连续工作面板不各自加阴影。边框不用纯黑，也不把控件边界降到不可辨认。

## 7. 页面结构与密度

### 7.1 Studio 聊天工作台

`全局导航 → 会话列表 → 主聊天区 → 按需显示的客户资料`

| 区域     | 桌面建议                    | 处理原则                   |
| -------- | --------------------------- | -------------------------- |
| 全局导航 | 192–216px                   | 品牌与模块清楚，不占主视觉 |
| 会话列表 | 300–340px                   | 能看见客户名、摘要与时间   |
| 聊天区   | 自适应，优先保留 480px 以上 | 正文易读，发送区可用       |
| 客户资料 | 264–296px                   | 次要信息，宽度不足优先收起 |

1440px 左右可四栏；空间不足先收资料栏，再折叠导航，不缩小消息字号。聊天区用 `--muted`，收到消息白色气泡，发出消息 `--brand-soft` 气泡，编辑器白色表面与阅读区形成分界。

### 7.2 列表页

页头 → 工具栏 → 列表或表格 → 分页。标题和主要操作位置稳定；搜索、筛选、批量操作属于列表，不漂浮在无关卡片中；不给整张表格套装饰性大卡片；摘要指标只在帮助决策且有真实数据时显示。

### 7.3 详情页

对象身份与当前状态 → 关键内容 → 可执行操作 → 历史和辅助信息。错误诊断可以占主区，失败原因不藏在页面底部；技术原始数据放可展开区域，不覆盖自然语言解释。

### 7.4 设置与连接页

清楚的分组、字段说明和保存范围。单列表单 640–760px 阅读宽度；有必要时两列，不铺满屏幕。内容少时调整容器宽度、位置和分组，不填无关统计或文案。

### 7.5 响应式

以内容是否还能正常阅读为断点依据，复用项目已有断点。

- 宽桌面：列表、主工作区和辅助资料同时展示。
- 中等宽度：资料以抽屉显示，主区保持舒适宽度。
- 平板：导航可折叠，保留列表与内容。
- 手机：列表和会话分屏切换，有明确返回路径；资料用抽屉或单独视图。
- 编辑器不被软键盘遮挡，消息区可独立滚动。
- 字体放大至 200% 时允许重排。

## 8. 聊天业务组件

### 8.1 会话行

顺序：头像 → 客户身份 → 公司或渠道辅助信息 → 最新消息摘要；时间和未读数靠右。

- 客户名首要，摘要其次，时间退后。
- 选中态用 `--brand-soft` 底和适度边界，可叠加细窄品牌标记，不同时堆叠多种强提示。
- 未读通过字重和计数表达，不把所有字段改成品牌蓝。
- 长名字和摘要省略，详情中提供完整内容。
- 行高按内容在 84–104px 调整，不为整齐截断必要状态。
- 有头像显示真实头像，无头像用统一色板的文字回退。
- 渠道图标用官方资产，不拿字母当平台 Logo。

### 8.2 消息

- 收到与发出通过对齐和表面共同区分，不只靠颜色。
- 气泡宽度不超过聊天区的 75–82%，手机可放宽。
- 同一人连续消息适度紧凑，不每条都重复头像和姓名。
- 时间、回执、编辑标识是辅助信息，不抢正文。
- 不为展示丰富度强制每条消息都有大头像、标签或卡片。

### 8.3 译文

原文与译文在同一消息上下文中展示，用间隔或细分隔线区分。译文不用 disabled 颜色；阅读顺序与用户配置一致。翻译未完成、翻译失败、未启用翻译分别表达。

### 8.4 图片与附件

- 产品图片保持真实比例，设最大显示尺寸，展示前预留空间。
- 文件展示类型、名称、大小和可用动作。
- 报价附件用紧凑文件组件，不生成另一张业务大卡片。
- 加载、上传、失败状态在附件自身位置表达。
- 下载和放大入口有明确点击反馈。

### 8.5 回复编辑器

回复模式、内容输入、必要工具和发送操作。边界清晰的白色容器；发送按钮品牌蓝，不可用时可识别但不误导；普通回复与内部备注有文字和视觉区分；AI、翻译、附件工具只在能力存在时出现；输入法、快捷键和多行行为一致。

### 8.6 客户资料

身份区含头像、姓名、公司和少量重要标签，其余按信息组组织，不每个字段一张卡片。字段标签弱于字段值但都要可读；关键业务备注可有独立浅色表面；标签色彩受控，同一语义跨页面一致；无数据不展示虚构占位。

## 9. Relay 专用表达

### 9.1 连接与账号

平台身份、账号名和连接状态容易扫描。账号与连接不是同一概念，界面名称遵守业务模型。连接失效给出恢复动作和原因，不用永久绿点暗示实时可用。

### 9.2 操作状态

区分已接受、排队、执行中、平台已接受、已送达和失败；并非每个渠道都有全部回执。「请求已提交」不等于「已送达」；结果待核实时明确说明，不强行归为成功或失败；不支持的状态显示能力限制；时间线只展示真实发生的事件。

### 9.3 日志与技术详情

时间、操作类型、对象、状态优先；长 ID 和原始 JSON 次之。先可读摘要，再按需展开。ID 截断显示并可完整复制。密钥默认遮蔽。表格靠对齐、数字格式和状态层次提高效率，不靠彩色背景。

## 10. 基础组件

基础组件在 `packages/ui/components`，ReUI 组件在 `packages/ui/components/reui`。

| 组件             | 使用规则                                                                     |
| ---------------- | ---------------------------------------------------------------------------- |
| Button           | primary 主要动作；outline 次级动作；ghost 低权重工具；destructive 仅危险动作 |
| Input / Textarea | 标题、说明、错误各自明确；不用 placeholder 充当标签                          |
| Badge            | 状态、类别或计数；常规用浅色或描边，少量强状态用实色                         |
| Tabs             | 切换同一上下文的视图；页面视图用下划线，局部模式可用分段样式                 |
| Dropdown         | 低频动作；高频主操作不埋入菜单                                               |
| Tooltip          | 短解释和图标名称，不承载唯一的重要说明                                       |
| Dialog           | 需要聚焦或决策时；简单查看用就地展开或抽屉                                   |
| Sheet / Drawer   | 辅助详情或窄屏资料；关闭后焦点返回触发入口                                   |
| Data Grid        | ReUI Data Grid；金额和数字对齐；行操作位置稳定                               |
| Toast            | 短暂反馈，不作为持久错误或关键状态的唯一展示                                 |
| Skeleton         | 接近最终结构的加载态，不整页闪烁                                             |

统一 hover、focus-visible、active、disabled、loading、error、selected 状态，不同语义不共用同一个颜色变化。复用基础组件的键盘导航、焦点管理、关闭机制和辅助技术支持。

## 11. 状态、文案与反馈

### 11.1 空状态

| 场景               | 表达重点                                     |
| ------------------ | -------------------------------------------- |
| 首次进入，没有账号 | 解释连接账号后能开始什么，给连接动作         |
| 已连接，暂无会话   | 说明消息到来后会出现的位置                   |
| 搜索无结果         | 展示当前条件，给清除或修改条件的入口         |
| 当前分类为空       | 说明该分类没有内容，不暗示故障               |
| 请求失败           | 保留上下文，说明未能加载什么以及可采取的动作 |

### 11.2 中文文案

- 动作明确的按钮：连接账号、保存更改、发送消息、重新连接。不用「提交」「确认操作」「处理异常」。
- 错误说明包含失败对象和可行下一步；技术详情保留原始错误码，Studio 的首层说明用用户语言。
- AI 建议、草稿和已发送消息清楚区分；未执行的动作不描述为已完成。
- 时间遵守产品时区；列表可用相对时间，诊断信息能查看精确时间。

### 11.3 动效

动效解释状态与空间关系。悬停和颜色变化 120–180ms；抽屉、弹窗 180–240ms。遵守减少动态效果偏好。不做列表弹跳、消息逐条入场、按钮循环发光。

## 12. 工程落地

### 12.1 三层

1. **共享主题**：`tooling/tailwind/theme.css` 的颜色、字体、圆角、阴影和密度基线。
2. **基础组件**：复用 `packages/ui` 的 Button、Input、Badge 等，统一必要变体。
3. **业务组件与页面**：会话行、消息、译文、附件、编辑器、资料分组与工作区布局，按需提炼 `ConversationItem`、`MessageBubble`、`MessageTranslation`、`MessageAttachment`、`MessageComposer`、`ContactSummary`。不预建空组件，不做页面配置系统。

### 12.2 定制原则

允许：修改主题，组合现有组件，增加少量语义明确的变体，编写业务布局 CSS。

避免：为某个外观引入另一套 UI 框架；在各页面复制粘贴按钮、菜单、输入框；硬编码任意色值和 `!important`；为品牌感重写底层弹窗、焦点和键盘交互。

主题能统一解决的先用主题；局部业务需求留在业务组件；修改基础组件时检查其他调用方。

## 13. 验收

### 13.1 整体

- 第一眼能识别当前任务和主操作。
- 导航、列表、内容和辅助信息关系清楚。
- 蓝色在品牌、选中态和动作之间形成一致联系。
- 页面有真实内容带来的丰富度，没有为填满空间加无关模块。
- 没有大面积相同白底、相同灰字、相同轻重的单薄效果。
- 主要信息正常可读，没靠缩小字体制造精致感。

### 13.2 组件与内容

- 客户名、摘要、时间与未读能快速分辨。
- 原文、译文、内部提示与已发送内容不混淆。
- 产品图片与文件附件呈现合适。
- 发送区边界清晰，工具优先级稳定。
- 状态文案与真实业务结果一致。
- 长姓名、多行中文、长 URL、阿语、失败和无数据状态不破坏布局。

### 13.3 技术与可访问性

- 正常、悬停、焦点、选中、禁用、加载与失败状态完整。
- 关键控件可用键盘访问，图标按钮有名称。
- 对比度按实际组合检查，颜色不是状态的唯一表达。
- 窄屏先重排或收起辅助区域，不压缩正文字号。
- 200% 文字缩放后仍可阅读和操作。
- 中文输入法不误发送；页面没有横向溢出。
